2

Validation & verification

Customer Journey on Portal

Apply the rules engine before employees can advance

The validation gate protects downstream onboarding by testing uniqueness, field formats, delivery requirements, and re-onboarding conditions.

Output: Pass / fail reasons
Identity & uniqueness

Find duplicates

  • Detect across SSN, Email/Phone, and Date of Birth.
  • Require unique SSN4 + Date of Birth per employee.
  • Check name formatting only; identity is not validated here.
Re-onboarding

Block duplicate journeys

  • Block already-onboarded employees.
  • Block users who began through the standard flow or a marketing link.
Field rules

Keep downstream data valid

  • Address format validation, including the legacy ZIP limitation for Corecard.
  • Proxy and Card Last 4 must be numeric.
  • International phone numbers are supported for Fortuna only.
Delivery requirements

Mandatory fields change with the card-delivery option

Onsite

Anonymized cards are always delivered to the office.

Home

Personalized cards are delivered home; a home address is required.

Office

Personalized cards are delivered to the office; each employee's home address is also required.

Why this is a hard gate

Employees do not move directly from import into account creation. The draft must first satisfy the rules tied to uniqueness, required data, card delivery, and downstream system compatibility.

Decision 1

Employment status controls Direct Deposit

The verification result determines whether the configured Direct Deposit instruction is executed.

Employment verified?
YesApply No, immediate, or deferred Direct Deposit behavior.
NoMark Pre-hire in Employer table; do not switch Direct Deposit.

View the complete 12-step processing sequence
  1. Log an event per submission.
  2. Create User and Employer records used by Better Auth.
  3. Run KYC via Persona and Sentilink.
  4. Verify employment via Prism/Asure; on failure, mark the employee Pre-hire in the Employer table.
  5. Create the Corecard account using the onsite or personalized-card path.
  6. Send Office/Home delivery instructions to Corecard.
  7. Mark the user ONBOARDED in the database.
  8. Apply the selected Direct Deposit option only for verified employment; do not switch for Pre-hire.
  9. Log an individual event per employee.
  10. Store failures in the database for a future Employer dashboard view.
  11. Send onboarding and invitation emails.
  12. Send SMS when email is missing.

Iteration 2

The next development priorities

These five improvements are explicitly identified in the technical flow as the next iteration.

01

Block ages 0-15

Add a rules-engine control that prevents employees in this age range from onboarding.

02

Consent for ages 16-18

Provide a downloadable parent consent form that the employer can distribute offline.

03

Deprecate the recent table

Remove the Recently Onboarded Users table, which currently persists across onboarding types.

04

Find users stuck before EWA

Identify ONBOARDED users who remain in the flow and have not enrolled for Earned Wage Access.

05

Move onsite requests into the portal

Create an Onsite Card Request form in the Admin Portal and move the current operational data into the database.
